# 性能与内存（Agent 备忘）

轻量工具箱：**用完即释**；RSS 不必回到冷启动，但**重复操作不应阶梯上涨**。

## 不要再犯的共性

- **隐藏 ≠ 释放**：只藏 UI 不拆引用，大对象和图层仍会驻留。
- **关闭路径要统一**：用户可能用按钮、快捷键、点外面等多种方式结束，都要走同一套收尾。
- **异步不能拖住 UI 数据**：会话结束后仍在跑的回调/Task 会继续持有已结束的视图和大块内存。
- **监听器要成对卸载**：全局/本地事件监听、Combine 订阅，创建与销毁对称。
- **控制器数组别只增不减**：长期持有的列表必须在结束时移除对应项。
- **复用窗口也要清空内容**：panel 不销毁时，关闭仍要 cancel 任务、清空文本/图片、断开闭包。
- **优先轻量实现**：能用简单规则解决的，别拉会常驻模型或缓存的框架。

## 新功能先想

- **谁持有、何时断**：创建→使用→结束的释放链是否完整。
- **峰值 vs 驻留**：瞬时涨内存可接受，关闭后业务数据应可回收。
- **大图/大文本**：少复制、少长期缓存，用完即 nil。
- **验证看趋势**：同一操作连续多次，应稳定在某个热基线，而非线性增长。

## 分派

- 改浮动 UI、异步流程、或排查内存 → 先读本文。
