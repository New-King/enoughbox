# 插件发布与审核

> 开源 EnoughBox **不等于** 开放随意上传插件。本文定义 **官方插件中心** 的政策；fork 者可自建规则。

---

## 1. 两层含义

| 层级 | 政策 |
|------|------|
| **EnoughBox 宿主（开源）** | 任何人可 fork、改宿主、自建 manifest、自签插件、自运营商店 |
| **官方 `plugin-registry`（本仓库）** | **Curated（审核制）**：仅合并经审核的 manifest 条目与 CI 构建产物 |

普通用户插件中心 **默认只读官方 manifest**，不能自行上传。

---

## 2. 官方插件怎么收录

```
第三方开发者
  → Fork 插件模板，开发 + 自测
  → 向本仓库提 PR（插件源码 + manifest 条目）
  → 维护者审核（代码、权限、兼容性）
  → CI 在固定环境 build .plugin → 签名 → 写 sha256
  → 合并 PR → 用户从插件中心可见
```

**不接受：**

- 仅提交 manifest 链接、指向个人服务器上未审核的二进制
- 跳过 CI、自行上传 zip 到 Releases 并要求直接收录（除非维护者代为验证后由 CI 发布）

**接受：**

- 插件源码在本仓库 `Plugins/<Name>/` 或独立 repo + submodule/发布流程（后期可定）
- PR 说明：测过的 macOS 版本、架构、所需权限、host 版本

---

## 3. 审核看什么

| 维度 | 说明 |
|------|------|
| **安全** | 无窃取 Keychain、无未声明的网络/文件访问、无混淆恶意行为 |
| **权限** | `capabilities` 与真实行为一致；少用权限 |
| **兼容性** | `minMacOS`、`architectures`、`minHostVersion` 准确 |
| **构建** | 官方 CI 产物可复现；非「仅在我电脑能跑」 |
| **质量** | 基本可用、崩溃不拖垮宿主（同进程加载，仍需谨慎） |

维护者 **不保证** 每台 Mac 环境一致；保证的是：**按声明的矩阵构建并在 CI 测过**。

---

## 4. manifest 字段（官方 registry）

文件：`plugin-registry/manifest.json`

### 顶层

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | number | manifest  schema 版本 |
| `hostMinVersion` | string | 读取本 manifest 所需的最低宿主版本 |
| `updatedAt` | string | ISO8601，可选 |
| `plugins` | array | 插件列表 |

### 每个插件

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 反向域名，全局唯一，如 `com.enoughbox.sample` |
| `version` | ✅ | SemVer |
| `name` | ✅ | 默认显示名（建议 en） |
| `nameLocalized` | 推荐 | `{ "en": "...", "zh-Hans": "..." }` |
| `description` | ✅ | 默认描述 |
| `descriptionLocalized` | 推荐 | 多语言描述 |
| `icon` | ✅ | SF Symbol 名 |
| `downloadUrl` | ✅ | **官方 CI 发布的** zip 地址 |
| `sha256` | ✅ | zip 的 SHA256（小写 hex） |
| `minHostVersion` | ✅ | 最低 EnoughBox 宿主版本 |
| `minMacOS` | ✅ | 最低 macOS，如 `14.0` |
| `architectures` | ✅ | `["arm64"]` 或 `["arm64","x86_64"]` |
| `capabilities` | ✅ | 见 §5 |
| `repositoryUrl` | 推荐 | 插件源码仓库 |
| `author` | 推荐 | 作者/id |

Phase 3 可选：

| 字段 | 说明 |
|------|------|
| `manifestSignature` | 整条 manifest 或单条插件的 Ed25519 签名（防篡改） |

## 5. capabilities（权限声明）

安装前 / 启用前，宿主根据声明提示用户（与 macOS TCC 配合）：

| 值 | 含义 | 典型插件 |
|----|------|----------|
| `hotkey` | 注册全局快捷键 | 多数插件 |
| `accessibility` | 辅助功能（划词等） | 翻译 |
| `screenRecording` | 屏幕录制 | 截图、OCR 屏上区域 |
| `network` | 出站网络（翻译 API 等） | 翻译 |
| `filesUserSelected` | 仅用户选中的文件 | 导出截图 |
| `clipboard` | 读写剪贴板 | 翻译、截图 |

宿主行为：

1. 安装时展示 capabilities 摘要  
2. 首次 `activate` 前，按 capability 触发系统权限或 EnoughBox 权限引导  
3. manifest 未声明但代码请求的敏感能力 → **审核拒绝**；运行时检测到可拒绝加载（Phase 3）

---

## 6. 架构与系统版本

| 问题 | 政策 |
|------|------|
| Apple Silicon / Intel | 官方插件 **必须** 声明 `architectures`；优先 **Universal**（arm64 + x86_64） |
| macOS 版本 | 与宿主 MVP 一致：`minMacOS: "14.0"` 起；插件可更高，不可更低于宿主支持范围 |
| EnoughBox 版本 | `minHostVersion` 与 SDK 能力对齐；破坏性 SDK 变更 → major bump |

CI 矩阵（目标，Phase 3 完善）：

- macOS 14 / 15 × arm64（必测）  
- x86_64 或 Universal 二进制（若 manifest 声明支持）

---

## 7. 签名与信任

| 阶段 | 策略 |
|------|------|
| **MVP / 自用** | SHA256 + 可选同 Team ID；Debug 可跳过 |
| **官方 registry** | CI 用 **维护者 Developer ID** 签名 `.plugin`；`sha256` 写入 manifest |
| **用户侧** | 仅安装官方 manifest 中的 URL；Gatekeeper + 哈希校验 |

未进入官方 registry 的包：**不支持**从插件中心一键安装（见 §8 sideload）。

---

## 8. Sideload（高级，默认关闭）

Phase 3 可选能力，**默认关闭**：

- 设置 → 开发者 →「允许安装本地/第三方插件」  
- 手动拖入 `.plugin` 或添加 **非官方** manifest URL  
- 宿主显示明确警告：未经审核，可能导致崩溃或安全风险  

官方插件中心 UI **不**提供随意上传入口。

---

## 9. 第三方 fork

Fork 维护者可：

- 替换默认 manifest URL 指向自己的 registry  
- 采用更松或更严的审核  
- 仅分发自用插件  

**无需** 向本仓库 PR；也 **不应** 冒用 `com.enoughbox.*` 官方 id 发布未审核包。

---

## 10. 贡献者 Checklist（PR 插件）

- [ ] `id` 唯一，未与现有插件冲突  
- [ ] 源码可审查，无硬编码密钥  
- [ ] `capabilities` 完整且最小化  
- [ ] `minMacOS` / `architectures` / `minHostVersion` 已填  
- [ ] `nameLocalized` / `descriptionLocalized`（en + zh-Hans）  
- [ ] 本地 arm64（及 Intel 若声明）自测通过  
- [ ] PR 描述：测试环境、功能说明、权限说明  

维护者合并前：

- [ ] 代码审核  
- [ ] CI build + 测试  
- [ ] 更新 `downloadUrl` + `sha256`
